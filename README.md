# Zorr WebSocket Bot Client ディレクトリ

このディレクトリは、ブラウザを使用せずに Zorr ゲームサーバーと直接 WebSocket 通信を行い、自動ナビゲーションや装備変更、ゲーム情報の可視化を実現する Node.js 製のスタンドアロン・ボットクライアント環境です。

---

## ディレクトリ構造

```
websocket/
├── README.md               — [本書] 環境概要と使い方
├── bot_session.js          — メインボットクライアント (LCG暗号化, パース, A*ナビゲーション, 自動巡回)
├── protocol_extractor.js   — [重要] Node VM上でゲームJSを実行し最新のプロトコルバージョンを自動抽出
├── game_data_loader.js     — ゲームデータ (ペタル/モブ/レアリティなど) の抽出とキャッシュ管理
├── game_data.json          — 抽出されたゲームデータのキャッシュファイル
├── map_server.js           — HTTP + SSE サーバー (ボットからの情報をブラウザに配信し、指示を仲介)
├── map.html                — リアルタイム・Webマップビューア (ブラウザでボット位置や周囲のモブを表示・操作)
├── build1.txt              — サンプル装備構成1 (base64エンコード済み)
├── build2.txt              — サンプル装備構成2 (base64エンコード済み)
├── build3.txt              — サンプル装備構成3 (base64エンコード済み)
└── start.bat               — 簡易起動バッチファイル
```

## システム構成とデータフロー

ボットシステムは、**ボット本体 (`bot_session.js`)**、**マップ中継サーバー (`map_server.js`)**、**WebUI (`map.html`)** の3つが連携して動作します。

```
                    ┌───────────────────────────┐
                    │  Zorr Game Server         │
                    │  (wss://s-*.zorr.pro/)    │
                    └─────────────┬─────────────┘
                                  │
                       WebSocket (LCG暗号化)
                                  │
                                  ▼
                   ┌─────────────────────────────┐
                    │  bot_session.js             │
                    │                             │
                    │  1. VMプロトコル抽出        │
                    │  2. パケット解析            │
                    │  3. A* ナビゲーション       │
                   └────────┬──────────────▲─────┘
                            │              │
                   POST /mapdata        GET /command (2秒ポーリング)
                   (100ms スロットル)   POST /ack (キュー消化)
                            │              │
                            ▼              │
                   ┌───────────────────────┴─────┐
                   │  map_server.js (:3000)      │
                   └────────┬────────────────────┘
                            │
                       Server-Sent Events (SSE)
                            │
                            ▼
                   ┌─────────────────────────────┐
                   │  map.html (ブラウザ画面)     │
                   │                             │
                   │  - マップ表示 / モブ位置    │
                   │  - クリックによる目的地指示  │
                   └─────────────────────────────┘
```

1. **起動フェーズ**:
   - `bot_session.js` 起動時に `protocol_extractor.js` を実行。最新のゲームJSを Node.js の VM (仮想マシン) サンドボックス内で実行させ、ゲームがWebSocket接続する際のハンドシェイクから**最新のプロトコルバージョン** (例: `444`) を動的に取得します。これにより、ゲームのアップデートによる `outdatedVersion` によるキックを自動的に回避します。
   - `game_data_loader.js` がゲーム内のペタル名・モブ名などを取得し `game_data.json` にキャッシュします。
2. **接続フェーズ**:
   - ボットがゲームサーバーに WebSocket 接続。LCG (線形合同法) ストリーム暗号を用いて初期ハンドシェイク (Opcode 0) を送信し、以降のパケット送信時に XOR 暗号を適用します。
3. **ループフェーズ**:
   - サーバーから送られる約 20fps のエンティティ更新情報 (Opcode 1 / 6) をリアルタイムでバイナリパース。
   - ボットは `map_server.js` (`POST /mapdata`) に対し、自機位置、装備ペタル、周囲のモブ情報などを 100ms ごとにスロットリングして送信します。
   - `map_server.js` は SSE (Server-Sent Events) 経由でブラウザ上の `map.html` にリアルタイムで描画データをプッシュします。
4. **ナビゲーションと指示**:
   - `map.html` でユーザーが任意の場所をクリックすると、`map_server.js` の `commandQueue` に移動指示 (`POST /navigate`) が格納されます。
   - ボットは 2秒間隔で `GET /command` をポーリングして指示を読み出し、`POST /ack` で処理完了を通知。A* ナビゲーション (`MinHeap`による高速化) で目的地へ移動を開始します。

## 使い方・起動手順

### 1. 依存関係のインストール
Node.js v22 以上が推奨されます。WebSocket通信を行うため `ws` ライブラリが必要です。（ボット起動時に自動インストールを試みますが、手動でインストールすることも可能です）

```bash
cd websocket
npm install ws
```

### 2. マップサーバーとボットの起動
`start.bat` を実行するか、手動で以下の2つのターミナルを立ち上げてください。

**ターミナル 1 (中継サーバー起動)**:
```bash
node map_server.js
```
*これにより、`http://localhost:3000` でマップサーバーが起動し、ブラウザでアクセスできるようになります。*

**ターミナル 2 (ボットクライアント起動)**:
```bash
# 単一アカウント起動 (bot_client.js 互換)
node bot_session.js

# 複数アカウント起動 (accounts.txt から読み込み)
node account_manager.js
```

### 3. ブラウザで監視と操作
ブラウザで [http://localhost:3000](http://localhost:3000) にアクセスします。
- ボットが取得したマップの壁と床の構造、自機、および周囲のモブがリアルタイムで描画されます。
- マップ上をクリックすると、ボットに目的地が指示され、ボットが自動で経路探索を行って移動します。

## 主要モジュールの詳細

### 1. `protocol_extractor.js` (VMベースの動的解析)
ゲームの最新コードは頻繁にアップデートされ、プロトコルバージョンが変更されます。本ファイルは以下のアプローチでこれを解決します：
- `zorr.pages.dev` の HTML から最新のゲームスクリプト URL を抽出してダウンロード。
- 全てのブラウザ API (Canvas, DOM, Navigator など) を Proxy を用いて再帰的にエミュレートしたセーフな VM サンドボックスを作成。
- その VM 内でゲームのJSを安全に部分実行させ、ゲームが WebSocket 接続を試行した際に送信される `Opcode 0` パケットをモックの WebSocket でインターセプト。
- パケットの `[1..4]` バイト目から Uint32 (リトルエンディアン) の**最新プロトコルバージョン**を自動抽出し、起動プロセスへ渡します。

### 2. `bot_session.js` (クラスベース版)
`bot_client.js` をクラスベースにリファクタリングし、`account_manager.js` から複数アカウントを管理できるようにしたメインボットクライアントです。
- A* アルゴリズムの `open list` の管理に二分ヒープによる優先度付きキュー (`MinHeap`, 挿入・取り出しともに $O(\log N)$) を採用。
- 全 Opcode 処理、LCG 暗号化、自動巡回 (Auto Patrol)、Pinky 検出、Discord 通知を統合。
